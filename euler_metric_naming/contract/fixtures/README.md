# Conformance fixtures

The golden material of [`docs/contract.md`](../../../docs/contract.md) §11.
An implementation of the contract is conformant when it reproduces every
expected value here. The Python package runs them in
`tests/contract/test_contract_conformance.py`, the TS artifact in
[`../ts/conformance.test.ts`](../ts/conformance.test.ts)
(`node --experimental-strip-types --test`).

Expected values were derived by hand from the spec, not by running an
engine. Hashes are SHA-256 over the canonical text written beside them.

| File | Format |
|---|---|
| `jcs.json` | `cases[]`: `{name, input, canonical}` — `canonicalize(input)` must equal `canonical`. `inputText` is JSON text to parse first; an all-digit `inputText` is integer-typed (Python `int`, JS `BigInt`). `special` is `NaN`, `Infinity` or `-Infinity`. `error: true` means canonicalization must fail. |
| `hashes.json` | `values[]` `{input, canonical, hash}`; `manifests[]` `{ids, canonical, hash}` (§9.3: NFC, de-duplicated, code-point order); `referenceIdentities[]` (§10); `definitionKeys[]` `{files, object, canonical, hash}`: the §9.4 object of the normalized contract of each listed eval file. |
| `conditions.json` | `parameters`, `observations` and `cases[]` `{condition, expected}`; `expected` is `true`, `false` or `unknown`. |
| `globs.json` | `cases[]` `{pattern, name, match}`. |
| `measures.json` | `measures[]` `{kind, a, b, d, phrase}` with label `L` (`d: null` = unmeasurable; compare `d` with tolerance 5e-7); `percent[]` `{d, text}`; `sig3[]` `{value, text}`. |
| `legacy.json` | `cases[]` `{protocol, metricSet, meta, expected, descriptorKeys}`: `normalize(protocol, metricSet, meta)` without `descriptors` and `reducers` must equal `expected`; `descriptors` must be exactly the legacy table's descriptors of `descriptorKeys`, `reducers` the table's reducers. |
| `references.json` | Reference identities across identity schemes (§8.5): `template` + `metricSet`; each case puts `a` and `b` under `references.gt` of the template, compares cell `metric` (both orders) and expects `tier`, `label`, `codes`, the first reason's `hint`. |
| `relevance.json` | `cases[]` `{a, b, metric, keys}`: `relevant_keys` / `relevantKeys` of the contracts of `evals/<a>` and `evals/<b>` (`b` null: `a` alone) must equal `keys` (code-point order). |
| `verdicts.json` | `cases[]` `{a, b, metric, tier, label, codes, shared, measures?, hint?, recompute?}`: load `evals/<a>` and `evals/<b>`, take item sets and per-item names from the files (`fileEvidence`), compare the cell `metric`. `codes` are the reason codes in order; `measures` the reasons with a measure, in order (`d` rounded to 6 decimals, tolerance 5e-7); `hint` the first reason's hint; `recompute` the aggregate recomputed on the shared items of each side (tolerance 1e-9). |
| `evals/*.json` | Complete `eval.json` files, importable by euler-view (camelCase `metricSet` envelope, nested metric tree, `per_file_metrics` with `children` / `files[{id, metrics}]`). |

## The eval files

Generated by [`scripts/generate_fixtures.py`](../../../scripts/generate_fixtures.py)
with `ProtocolBuilder` (a test fails when they are out of date). Depth files
use the `depth.eval` namespace with axes `space` (required), `category`,
`reduction`, `bin`; metric space values are `0.10 + 0.01·k` for `absrel` of
item `day-k` (`night-k` is `k + 10`), native space `+0.02`, plus a per-file
offset; the `count` weights are `1000 + 100·k`.

| File | What it is |
|---|---|
| `d1` | DepthPro on GT `cropped` (view of `cerema/rgb_left@1024x1920`, region `[270,170,734,1730]`), cap 38 m with `depth.cap.clipped` > 0, bins of [0.01, 32] m, alignment not applied, items `day-0..5` |
| `d1b` | `d1` with nothing clipped by the cap |
| `d2` | MARI: same GT, domain `[270,170,728,1728]` (VAE crop) |
| `d3` | DepthPro on GT `full_crop` (another identity, same source, region `[270,170,707,1730]`) |
| `d4` | `d1` on `night-0..5` |
| `d5` | MoGe: cap 120 m, bins of [0.01, 100] m, `day-0..5` + `night-0..2` |
| `d5b` | `d5` with `d1`'s bins and nothing clipped |
| `d6` | night, resized (`prediction.resample` [1.04, 1.02]) and fitted (`depth.alignment.applied`) |
| `d7` | night, fitted, not resized |
| `d8` | `d1` on `day-0..2` |
| `d9` | `d1` with `absrel` at `rev` 2 |
| `d10` | `d1` plus an undescribed parameter `depth.debug.tile_px` |
| `d10u`, `d10v` | descriptors with an unknown role (`tuning`), with and without `compare: ignore` |
| `u1`, `u2` | schema `3.0` (unsupported major); `u2` with another cap |
| `l1`–`l5` | legacy schema 1.3 (euler-eval 2.47), GT dataset `cerema`: `l1` cropped/none 734×1730 rev 3, `l2` vae_crop 728×1728, `l3` a per-file subset, `l4` without per-file metrics, `l5` another GT dataset (`kitti`) |
| `m1`, `m3` | legacy muses-like pair, metrics revision 1 vs 3, hierarchical per-file ids (`night~frame-0`) |
| `r1`–`r4` | RGB-like files without a reduction axis: metrics carry an implicit `reducer` (`image_mean` for PSNR and the binned MAE, `dataset` for FID); fixed GT-depth bins `[0, 1, 5, null]` (open far bin). `r2` a subset with other values, `r3` edges `[0, 1, 10, null]`, `r4` `[null, 1, 5, null]` |
| `s1`–`s6` | a synthetic modality (`audio.eval`) no vocabulary knows: every term comes from the files' own snapshots. `s2` truncated audio, `s3` sample rate, `s4` subset, `s5` SNR edges, `s6` denoising that does not apply |

## Training runs

[`docs/training.md`](../../../docs/training.md) §7. `training/documents.json` is
generated by `scripts/generate_fixtures.py` (MetricNamespace and
ProtocolBuilder, the way producers should write them); `training/cases.json`
holds the expected results, written by hand from the spec.

| File | Format |
|---|---|
| `training/documents.json` | `declarations` (training naming declarations by name), `sets` (validation set documents by name), `passes` (`{set, record}` by name: a pass record and the name of its set) |
| `training/cases.json` | `declarations[]` `{declaration, problems}`: `training_naming_problems` / `trainingNamingProblems` as `{code, path}` in order. `keys[]` `{declaration, key, problem, definition}`: the problem code of `training_metric_problem` (or null) and the result of `training_metric_definition`, given as `{namespace, base}` of the declared definition (or null). `sets[]` / `passes[]` `{set or pass, problems}`: `validation_set_problems` / `validation_pass_problems`. `contracts[]`: fields of `validation_pass_contract` (`itemIds` = `items.ids` or null, `populationCount`, a subset of `parameters` and `observations`, `seriesNames` sorted). `verdicts[]`: as `verdicts.json`, where `a` and `b` are `pass:<name>` (loaded with `load_validation_pass`) or `eval:<file of evals/>`; each case is also checked in both orders |

The validation sets are built over the GT of `evals/d1` with d1's settings;
their passes carry d1's metric-space values, so a pass on d1's items reads
`same protocol` against d1 and a pass on half of them `compared on 3 shared
files` with equal recomputed values.
